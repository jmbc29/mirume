# Mirume

A macOS desktop overlay for learning Japanese. Hover over Japanese text anywhere
on screen and Mirume detects it, classifies every word and grammar pattern by
JLPT level (N5–N1), and shows a hover card with reading, meaning, and
difficulty. Save words, sentences, and grammar patterns to a local SQLite
database and review them later with SM-2 spaced repetition. Everything stays on
your machine.

## Project layout

```
mirume/
  backend/     FastAPI server + Japanese NLP (this is what runs today)
  frontend/    Tauri + React transparent overlay (not scaffolded yet)
  data/        Generated SQLite databases + raw JMdict/kanjidic2 XML
  models/      Saved PyTorch model files (gitignored)
```

## Backend — getting started

Requires Python 3.11+ and macOS.

```bash
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r ../requirements.txt

# One-time: download JMdict + kanjidic2 and build data/jmdict.db (~12 MB
# download, ~1 min). Re-run with `build --force` to refresh the sources.
python jlpt.py build

# Port 8123 avoids a conflict with another local project on 8000.
uvicorn main:app --reload --port 8123
```

**Accessibility permission (macOS):** `/hover` reads on-screen text via the
Accessibility API. Grant permission in **System Settings ▸ Privacy & Security ▸
Accessibility** to the app running the server (your terminal, or Python), then
restart it. Without it, `/hover` always returns the placeholder sentence
(`source: "placeholder"`). Verify detection with `python accessibility.py`.

The server listens on `http://127.0.0.1:8123`. Interactive API docs are at
`http://127.0.0.1:8123/docs`.

### Endpoints implemented so far

| Method | Path      | Status | Description |
| ------ | --------- | ------ | ----------- |
| GET    | `/health` | done   | Liveness check; reports DB paths, dictionary-built and accessibility-permission status. |
| POST   | `/hover`  | done   | Accepts `{x, y}`. Reads real on-screen text at that point (AX API), tokenises it and returns JLPT classifications, meanings, readings and a per-kanji breakdown. Falls back to a placeholder sentence when nothing is detected. |

Planned: `/save/word`, `/save/sentence`, `/save/grammar`, `/review`, `/stats`.

### Dictionary data (`data/`, all gitignored)

| File | Source | Used for |
| ---- | ------ | -------- |
| `jmdict_e.xml` | [EDRDG JMdict](http://ftp.edrdg.org/pub/Nihongo/JMdict_e.gz) | word readings + meanings |
| `kanjidic2.xml` | [EDRDG kanjidic2](http://www.edrdg.org/kanjidic/kanjidic2.xml.gz) | per-kanji readings + meanings |
| `jlpt_vocab/n{1..5}.csv` | [elzup/jlpt-word-list](https://github.com/elzup/jlpt-word-list) (Tanos lists) | word-level JLPT tags |
| `kanji_data.json` | [davidluzgouveia/kanji-data](https://github.com/davidluzgouveia/kanji-data) | estimated *new* JLPT kanji levels |
| `jmdict.db` | generated by `jlpt.py build` | `Entry` + `Kanji` tables queried at runtime |

JMdict has no official JLPT tags, so word levels come from the community-standard
(pre-2010) Tanos lists. Words on no list but made of known kanji get an estimated
level from their hardest kanji (`jlpt_estimated: true` in API responses).

### Backend modules

| File               | Responsibility |
| ------------------ | -------------- |
| `main.py`          | FastAPI app + routes |
| `database.py`      | SQLAlchemy engines/sessions for `jmdict.db` and `mirume.db` |
| `models.py`        | `SavedWord`, `SavedSentence`, `SavedGrammar`, `WordEncounter` |
| `tokeniser.py`     | fugashi + MeCab tokenisation (surface / reading / lemma / POS) |
| `jlpt.py`          | JMdict/kanjidic2 parser + `Entry`/`Kanji` tables + `lookup` / `classify_tokens` / `get_kanji_breakdown` |
| `accessibility.py` | macOS AX API text detection — `get_text_at_position` / `get_focused_text` + permission handling |
| `ocr.py`           | *(planned)* manga-ocr fallback for images |
| `grammar.py`       | *(planned)* JLPT grammar pattern detection |
| `difficulty.py`    | *(planned)* sentence difficulty scorer |
| `spaced_rep.py`    | *(planned)* SM-2 review scheduling |
| `personalisation.py` | *(planned)* local PyTorch knowledge model |
